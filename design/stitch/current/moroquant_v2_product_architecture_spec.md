# MoroQuant V2 Product Architecture

## 1. Information Architecture
MoroQuant V2 is structured as a multi-workspace Operating System. Instead of a flat navigation structure, it uses a hierarchical workspace-switching model to provide specialized environments for different phases of the quantitative trading lifecycle.

### Global Workspace Navigation (Primary Sidebar)
- **🏦 Trading**: Operational environment for live system management and execution.
- **🧪 Research Lab**: Scientific environment for model development, validation, and governance.
- **⚙ Operations**: Infrastructure environment for platform reliability, scheduling, and health.

---

## 2. Workspace Hierarchy & Page Structure

### Workspace 1: TRADING
*Identity: High-velocity, real-time telemetry, market-focused.*
- **Dashboard**: Global PnL, equity curves, and system exposure.
- **ML Signals**: Real-time model predictions and confidence scoring.
- **Portfolio**: Capital allocation, sector exposure, and rebalancing.
- **Trades**: Active position monitor and historical trade blotter.
- **Execution**: Sub-millisecond order flow, slippage, and LBM latency.
- **Risk**: Stress testing (Monte Carlo), Greek ladders, and VaR.
- **Analytics**: Market regime performance and confidence distribution.

### Workspace 2: RESEARCH LAB
*Identity: Analytical, pipeline-driven, inspector-heavy.*
- **Command Center**: Mission control for active training/validation jobs.
- **Chronicle**: Lifecycle visualization (GitHub Actions style).
- **Experiments**: Hyperparameter exploration and metrics comparison.
- **Datasets**: Lineage, integrity, and versioned data catalog.
- **Feature Registry**: Dependency graphs and Gini importance metrics.
- **Validation**: Purged walk-forward visualizations and fold analysis.
- **Calibration**: Brier scores and reliability diagrams.
- **Registry**: Model governance, promotion, and deployment logs.
- **Trade Forensics**: Post-trade deep-lineage audit tool.

### Workspace 3: OPERATIONS
*Identity: Monitoring-centric, infrastructure-aware, log-heavy.*
- **Scheduler**: Directed Acyclic Graph (DAG) for automated jobs.
- **Workers**: GPU/CPU node utilization and worker cluster health.
- **Monitoring**: System-wide alerting and heartbeat telemetry.
- **Logs**: High-performance streaming application logs.
- **Settings**: Global configuration and API management.

## 3. Visual Identity & Workspace Markers
While sharing the **Institutional Quant Core (MQDS)** design system, each workspace utilizes subtle visual markers to provide immediate context:

| Feature | Trading | Research Lab | Operations |
| :--- | :--- | :--- | :--- |
| **Primary Theme** | Pure Black (#090909) | Pure Black (#090909) | Pure Black (#090909) |
| **Accent Tone** | Institutional Orange (#FF6B00) | Slate / Orange Accents | Terminal Green / Orange |
| **Core Layout** | Chart-heavy, real-time | Table-heavy, Inspector-right | Log-heavy, Terminal-bottom |
| **Typography** | JetBrains Mono (Data focus) | IBM Plex Sans (Label focus) | JetBrains Mono (Code focus) |
| **Interaction** | Hotkeys / Quick Actions | Deep Filtering / Drill-down | Status Indicators / Toggles |

---

## 4. User Flow
1. **Model Development (Research Lab)**: Researcher develops a feature → runs experiment → validates → promotes to registry.
2. **Operational Deployment (Operations)**: Platform engineer monitors the scheduler to ensure the model worker is healthy and logs are clean.
3. **Live Execution (Trading)**: Trader monitors the signal generated by the model → observes execution quality → reviews risk exposure.
4. **Continuous Learning (Research Lab)**: Trade forensics traces a loss back to a feature drift in the original dataset.
